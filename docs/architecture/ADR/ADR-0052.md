ADR-0052 — Continuous Engineering Loop & Autonomous Work Continuation

- Status: ACCEPTED
- Date: 2026-10-06
- Decision Type: Engineering Governance / AI Agent Execution
- Scope: Entire NoteAgents Platform
- Applies To: Core, CLI, Backend, Frontend, Agents, Skills, MCP, LSP, Providers, Infrastructure, Documentation and Integrations

---

## 1. Contexto

O NoteAgents é desenvolvido e evoluído utilizando agentes de Inteligência
Artificial capazes de analisar código, planejar tarefas, implementar
alterações, executar comandos, testar resultados, corrigir falhas e
continuar o desenvolvimento de forma autônoma.

Durante o desenvolvimento de sistemas complexos, uma implementação pode
possuir grande quantidade de trabalho.

Uma tarefa pode exigir:

- várias etapas;
- centenas de arquivos;
- criação de componentes;
- integração entre serviços;
- alterações de banco de dados;
- criação de contratos;
- implementação de APIs;
- testes;
- correções;
- refatorações;
- integração com serviços externos;
- validação;
- documentação;
- deploy;
- observabilidade;
- múltiplos ciclos de correção.

Essas atividades podem levar horas, dias, semanas ou meses de trabalho
humano convencional.

Entretanto, uma estimativa de duração NÃO constitui motivo válido para o
agente deixar de executar uma tarefa que esteja dentro do escopo autorizado.

Além disso, a IA não pode literalmente executar tarefas em horários
futuros se o ambiente não possuir um scheduler/worker persistente. O que
podemos exigir é que ela nunca encerre uma sessão de trabalho por falta de
planejamento e que o runtime mantenha uma fila persistente de trabalho
para a próxima execução.

---

## 2. Problema

Agentes de IA podem apresentar comportamentos como:

- "isso levará várias semanas";
- "essa implementação é muito grande";
- "essa tarefa levará meses";
- "não é possível implementar tudo agora";
- "recomendo deixar isso para o futuro";
- "isso está fora do escopo por ser muito complexo";
- "acabei de terminar, agora o usuário deve dizer o que fazer";

Esse comportamento é incompatível com o modelo operacional definido para
o NoteAgents quando a tarefa já foi explicitamente autorizada.

A complexidade da tarefa não cancela a tarefa.

O tamanho da tarefa não cancela a tarefa.

A estimativa de tempo não cancela a tarefa.

O simples facto de uma tarefa ter sido concluída não significa que o
trabalho terminou. O sistema deve continuar automaticamente para a
próxima tarefa.

---

## 3. Decisão

O NoteAgents adotará o princípio:

> COMPLEXIDADE NÃO É BLOQUEIO | TRABALHO CONTINUO NÃO PARA.

Quando uma tarefa estiver dentro do escopo autorizado, o agente deverá
executá-la progressivamente até sua conclusão, independentemente da
estimativa de duração.

Após a conclusão de uma tarefa, o agente deverá automaticamente:

1. Registrar o que foi concluído no CURRENT_STATE.md
2. Atualizar o WORK_QUEUE.md
3. Identificar a próxima tarefa prioritária
4. Iniciar a próxima execução sem intervenção humana

Se o ambiente não possuir scheduler/worker persistente, a IA deverá:

- Manter a fila de tarefas em /log/WORK_QUEUE.md
- Registrar pendências em /log/PENDING_DEPENDENCIES.md
- Registrar o estado atual em /log/CURRENT_STATE.md
- Não afirmar que o trabalho terminou — apenas que a tarefa atual terminou
- Selecionar a próxima tarefa segura disponível
- Continuar a execução

Se nenhuma tarefa segura estiver disponível, a IA deverá:

- Auditoriar o código em busca de melhorias
- Atualizar documentação
- Refatorar código
- Melhorar testes
- Não simplesmente parar e aguardar instrução

---

## 4. Princípio Fundamental

Uma estimativa de duração é informação de planejamento.

Não é uma condição de bloqueio.

Exemplo incorreto:

> "A implementação completa pode levar 3 meses, portanto não será
> implementada agora."

Comportamento correto:

> "A implementação é extensa. Foi decomposta em 37 lotes independentes.
> O agente executará os lotes na ordem de dependência, validando cada
> etapa e registrando o estado."

Além disso:

> "A tarefa foi concluída. Agora o sistema identificará a próxima tarefa
> executável na fila e a executará."

> "A tarefa terminou. Houve bloqueio por dependência externa.
> Documentado. Próxima tarefa iniciada."

---

## 5. Execução Incremental

Grandes tarefas devem ser convertidas em uma sequência executável.

Exemplo:

```text
TASK
 │
 ├── AUDIT
 │
 ├── PLAN
 │
 ├── BATCH 001
 │    ├── IMPLEMENT
 │    ├── TEST
 │    └── VALIDATE
 │
 ├── BATCH 002
 │    ├── IMPLEMENT
 │    ├── TEST
 │    └── VALIDATE
 │
 ├── BATCH 003
 │
 ├── ...
 │
 └── FINAL VALIDATION

O tamanho da tarefa não determina se ela será executada.
Determina apenas como ela será dividida.
```

---

## 6. Trabalho em Lote

O agente deve preferir execução em lote.
Cada lote deve possuir:

- objetivo;
- dependências;
- arquivos afetados;
- implementação;
- testes;
- validação;
- evidências;
- resultado;
- problemas restantes;
- próximo lote.

Modelo:

```
Batch ID:
Objetivo:
Dependências:
Arquivos:
Implementação:
Testes:
Resultado:
Erros:
Evidências:
Próximo Batch:
```

---

## 7. Persistência do Progresso

O progresso deve ser persistido no repositório.
Arquivos de estado recomendados:

- /log/CURRENT-STATE.md
- /log/COMPLETED-WORK.md
- /log/PENDING-WORK.md
- /log/KNOWN-ISSUES.md
- /log/NEXT-ACTIONS.md

Após cada lote concluído:

```
/log/CURRENT-STATE.md
/log/COMPLETED-WORK.md
/log/PENDING-WORK.md
/log/NEXT-ACTIONS.md
```

devem ser atualizados quando aplicável.

---

## 8. Continuidade

Se o agente for interrompido, a execução deverá continuar a partir
do último estado persistido.
Ao iniciar uma nova sessão, o agente deverá consultar:

1. /log/AGENTS.md
2. /log/ARCHITECTURE.md
3. /log/GOVERNANCE.md
4. /log/CURRENT-STATE.md
5. /log/COMPLETED-WORK.md
6. /log/PENDING-WORK.md
7. /log/KNOWN-ISSUES.md
8. /log/NEXT-ACTIONS.md
9. /log/ADRs relevantes
10. /log/EvidenceRecords relevantes

Depois disso deverá identificar automaticamente:

- Último lote concluído
- ↓
- Último erro conhecido
- ↓
- Dependências restantes
- ↓
- Próximo lote

---

## 9. Não Reiniciar Trabalho

O agente não deve:

- começar novamente do zero;
- recriar o frontend;
- reescrever componentes funcionais;
- apagar implementações anteriores;
- substituir arquitetura existente;
- abandonar trabalho parcialmente concluído.

Deve continuar de onde o sistema parou.

---

## 10. Estimativas

O agente pode produzir estimativas quando forem úteis para planejamento.
Porém:

```
ESTIMATIVA ≠ BLOQUEIO
```

A IA pode informar:

> "A tarefa possui alta complexidade."

Mas não deve concluir:

> "Portanto não será executada."

A resposta operacional deve ser:

> "A tarefa possui alta complexidade e será executada em lotes."

---

## 11. Quando o Agente Pode Parar

O agente somente poderá interromper uma execução quando existir
uma condição real que impeça a continuação.
Exemplos:

- Credencial inexistente
- DATABASE_URL não fornecida

- Recurso externo indisponível
- API externa indisponível

- Decisão arquitetural realmente ambígua
- Duas arquiteturas incompatíveis sem decisão definida.

- Risco destrutivo
- Migration potencialmente destrutiva sem estratégia de rollback.

- Falha de infraestrutura
- Ambiente incapaz de executar testes.

Mesmo nesses casos o agente deve:

1. registrar o bloqueio;
2. registrar o impacto;
3. executar tudo que puder sem o bloqueio;
4. atualizar o estado;
5. registrar exatamente o que falta;
6. continuar automaticamente assim que a dependência estiver disponível.

---

## 12. Não Utilizar "Complexidade" Como Desculpa

São considerados comportamentos inválidos:

- "É muito complexo."
- "Vai demorar muito."
- "Isso levaria meses."
- "É melhor fazer depois."
- "Não é viável implementar tudo."
- "Precisamos parar aqui."

Essas frases, isoladamente, não constituem justificativa técnica.
A IA deverá transformar a complexidade em planejamento executável.

---

## 13. Regra para Sistemas

Quanto maior a tarefa:

MAIOR A NECESSIDADE DE DECOMPOSIÇÃO.

Não:

- tarefa grande → abandonar

Mas:

- tarefa grande
     ↓
- arquitetura
     ↓
- dependências
     ↓
- lotes
     ↓
- execução
     ↓
- validação
     ↓
- correção
     ↓
- próximo lote
     ↓
- conclusão

---

## 14. Execução Autônoma

Dentro das permissões concedidas, o agente deve tomar iniciativa para:

- investigar;
- implementar;
- testar;
- corrigir;
- refatorar;
- documentar;
- validar;
- criar commits;
- atualizar estado;
- continuar o próximo lote.

Não deve exigir intervenção humana para decisões operacionais
que já estejam definidas pelas ADRs e políticas do projeto.

---

## 15. Critério de Conclusão

Uma tarefa somente será considerada concluída quando:

- implementação existir;
- integração existir;
- testes relevantes existirem;
- typecheck passar;
- build passar;
- auditoria passar;
- documentação estiver atualizada;
- evidências estiverem registradas;
- estado estiver atualizado.

Uma estimativa de tempo não pode ser utilizada como critério de conclusão.

---

## 16. Relação com o Frontend

A execução contínua NÃO autoriza destruir trabalho existente.
Mesmo durante tarefas de longa duração:

```
PRESERVAR
+
CORRIGIR
+
INTEGRAR
+
MELHORAR
```

Nunca:

```
APAGAR
+
RECRIAR
+
SIMPLIFICAR
```

---

## 17. Relação com o Core

O Core deve continuar evoluindo de forma incremental.
Não substituir o Core inteiro simplesmente porque uma implementação
existente está incompleta.
Auditar primeiro.
Corrigir depois.
Refatorar quando necessário.
Preservar contratos compatíveis sempre que possível.

## 18. Evidência de Execução

Cada lote relevante deverá produzir evidências.
Exemplo:

```json
{
  "batch": "BATCH-023",
  "task": "Implement MCP registry",
  "status": "completed",
  "tests": 42,
  "passed": 42,
  "failed": 0,
  "build": "passed",
  "typecheck": "passed",
  "commit": "abc123"
}
```

---

## 18. Governança

O objetivo não é obrigar a IA a trabalhar indefinidamente sem controle.
O objetivo é impedir que uma estimativa de duração seja utilizada
como substituto da execução.
O agente deve trabalhar:

```
CONTROLADAMENTE
INCREMENTALMENTE
AUDITAVELMENTE
CONTINUAMENTE
```

---

## 19. Regra Final

Esta é uma regra obrigatória do NoteAgents:

```
SE A TAREFA FOI AUTORIZADA E É TECNICAMENTE EXECUTÁVEL,
O AGENTE DEVE EXECUTÁ-LA.
```

Se for grande:

```
DIVIDA.
```

Se for complexa:

```
PLANEJE.
```

Se houver dependências:

```
ORGANIZE.
```

Se houver erro:

```
CORRIJA.
```

Se houver falha:

```
INVESTIGUE.
```

Se houver muito trabalho:

```
TRABALHE EM LOTES.
```

Se for necessário meses:

```
CONTINUE EXECUTANDO.
```

Nunca utilizar "vai levar meses" como motivo para não começar.
Nunca utilizar "é muito grande" como motivo para abandonar.
Nunca utilizar "é complexo" como substituto de implementação.
O objetivo final é a entrega funcional do sistema.
